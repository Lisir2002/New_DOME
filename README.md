# SNG —— 三身份通用大模型架构原型

**State-Navigated Generative**：一种市面上没有的新大模型架构 —— 把「决策 / 知道 / 说话」解耦为**三个独立、可替换、可组合的身份**：

- **主控制器**（30~50MB，唯一常驻主模型）：负责理解与调度，**只调配、不说话**
- **附属插件**（每个 ≤80MB，可下载）：各自持有领域能力，**默认关机、按需开机**
- **Echo-er**（≤80MB）：读结论池，**负责组织优化总结输出**

核心骨架与领域无关；**领域适配 = 下载对应插件文件 → 注册 → 即用，无需重训核心**。

> 当前为本仓库的**可运行原型**（首个验证基准：迷你文本游戏），用于验证全部核心机制。31 项基础测试全部通过。

---

## 为什么是"三身份"研究级亮点

| 命题 | 说明 |
|---|---|
| 小控制器是稀缺品 | 编排调度通常是大模型专利，30~50MB 专训调度模型是研究空白 |
| 插件可独立替换 / 升级 | 加能力 = 加文件；领域适配 = 下载插件即注册即用，骨架不动 |
| Echo-er 分离生成 | 输出质量（双语、叙事风格）可独立强化，不被其他身份牵制 |
| 有状态调度 | 控制器基于内置状态引擎调配，调度决策可验证，优于 LLM agent 的无根基工具调用 |
| 组合单调性（N+1≥N） | 加插件应让系统更强，是贯穿的核心命题 |

## 数据流（黑板池式 + 电源管理）

```
用户输入
   │
   ▼
① 主控制器 ───────────── 常驻（通用骨架），理解 + 状态引擎判任务，只调配
   │  写【指令池】
   ▼
【指令池】────────────── 集中仲裁 → 插件开机 / 关机名单（预算硬约束）
   │  插件自判断器（纯规则）双重校验，防主模型分配错误
   ▼
② 插件（各 ≤80MB）────── 默认关机；被放行的才开机处理
   │  结果有条理写【结论池】
   ▼
【结论池】── 验证器（内置）校验 ──▶ 通知 Echo-er
   │
   ▼
③ Echo-er（≤80MB）────── 读结论池，处理优化总结，输出
   │
   ▼
最终输出
```

**电源管理**：插件默认关机（零内存 / 零算力 / 零延迟），仲裁放行才开机；**按需开机、用完即停** —— 演示中聊天轮只开机 `chat`（11.5MB），游戏轮只开机 `domain + memory`（16MB）。

## 核心机制

- **WS 状态读写层**：持久状态矩阵 `S ∈ R^{128×128}`，跨回合读写；类型化槽语义固定直写 + 自由槽 content-based 软寻址
- **CRM 可编译规则记忆层**：规则表训练时可微索引学习，推理时编译为 DFA 迁移表（O(1) 确定性查表）
- **SVSL 自验证循环头**：计算图内的验证循环（≤K 次），验证打分器 + 修正头，保证状态一致性
- **调度头**：从上下文 + 状态读取生成调度决策（`task_types[]` / `candidate_plugins` / `complexity`），直接监督引擎真值插件集合
- **双层校验**：集中仲裁（主推）+ 插件自判断器（纯规则纠错）
- **统一训练目标**：多损失项加权，端到端可训练

## 目录结构

```
sng/
├── config.py            # 全局配置（内存预算、超参数、任务类型→插件先验）
├── pipeline.py          # 端到端链路：控制器→指令池→插件→结论池→Echo-er
├── training.py          # 统一训练循环（数据引擎 + 多损失 + 分阶段）
├── main.py              # CLI 演示（训练 + 交互）
├── echoer.py            # Echo-er：结论池组织输出，中英双语
├── core/
│   ├── controller.py    # 主控制器完整前向（WS + CRM + SVSL + 调度头）
│   ├── ws.py            # WS 状态读写层（128×128 + 混合寻址）
│   ├── crm.py           # CRM 可编译规则记忆层（可微索引 + DFA 编译）
│   ├── svsl.py          # SVSL 自验证循环头
│   ├── dispatch.py      # 调度头（任务类型 + 插件选择 + 复杂度）
│   └── pool.py          # 池式消息总线 + 电源管理 + 集中仲裁
├── engine/
│   ├── world.py         # 迷你文本游戏引擎（状态 / 规则 / 调度标注数据源）
│   └── vocab.py         # 中英双语词表与分词
└── plugins/             # 可下载插件（独立文件）
    ├── base.py          # 插件基类与清单规范
    ├── domain.py        # 领域插件（动作可行性判断）
    ├── memory.py        # 记忆插件（当前状态回忆）
    ├── lingua.py        # 双语插件
    └── chat.py          # 通用对话插件（域外兜底）
tests/                   # pytest 测试（31 项）
SNG-design.md            # 完整架构设计文档
```

## 快速开始

```bash
# 1. 安装依赖（Python 3.10+，PyTorch ≥2.0）
pip install torch pytest

# 2. 运行测试
pytest tests -q

# 3. 训练控制器（首次运行，约几分钟）
python -m sng.main --train

# 4. 交互演示（游戏 + 通用对话，中英双语）
python -m sng.main
python -m sng.main --lang en
```

## 交互示例

```
> 去厨房
【状态】当前记忆：你位于厨房，背包里有钥匙；大门锁着。
【分析】你位于厨房，此处物品有面包；大门锁着。动作「去厨房」可以执行：该房间可达。
【结果】状态更新已通过一致性验证，可以继续行动。
  · 动作=go 规则=move_valid 验证=通过 峰值内存=16.0MB

> 你是谁
【回复】我是 SNG 三身份模型系统：由主控制器统一调度，按需唤醒领域插件，再由 Echo-er 整理输出。…
  · 模式=chat 唤醒=['chat'] 峰值=11.5MB
```

文本游戏指令：`查看` / `去{房间}` / `拾取{物品}` / `放下{物品}` / `打开大门` / `背包`；也可自由闲聊。

## 领域适配

想接入新领域（如问答、代码、数学……）只需：

1. 新建插件文件，继承 `BasePlugin`，声明 `PluginManifest`（能力 / 体积 / 任务类型）
2. 在 `pipeline.py` 注册插件
3. 用该领域数据训练插件模型（或规则实现）

核心骨架、控制器、Echo-er 均无需改动。
